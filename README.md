# DT G1 Map Tools (ATS3085S Platform)

Набор утилит на Python для реверс-инжиниринга, анализа и компиляции кастомных оффлайн-карт для смарт-часов **DT NO.1 G1** (и других устройств на базе аппаратной платформы **ATS3085S**).

Проект представляет собой полностью открытую реализацию компилятора и декомпилятора закрытого бинарного картографического формата. Инструментарий позволяет извлекать заводские карты в формат GeoJSON, а также собирать собственные карты из открытых источников (например, OpenStreetMap), которые аппаратно поддерживаются и рендерятся прошивкой часов.

## ⚠️ Дисклеймер
> Это неофициальный проект, созданный исключительно методом реверс-инжиниринга ("черного ящика" и побайтового анализа дампов памяти). Использование утилит и загрузка модифицированных файлов в часы осуществляется на ваш страх и риск.

## 🛠 Состав инструментария

На данный момент кодовая база обеспечивает стопроцентную бинарную совместимость с аппаратным парсером часов и включает в себя:

* `dtg1_map_specification.md` — **Эталонная техническая спецификация формата (Версия 4.0).** Содержит полную структуру файлов `.mlp`, `.idx`, `.db`, спецификацию архитектуры C-Union, режимы переключения LOD и алгоритмы парсинга прошивки.
* `dtg1_map_compiler.py` — Компилятор карт версии 2.1. Автоматически парсит исходный XML-файл OpenStreetMap (`map.osm`), выполняет валидацию топологии полигонов, распределяет объекты по уровням детализации и генерирует готовые бинарные наборы (`.mlp`, `.idx`, `.db`) для слоев дорог, водоемов и землепользования.
* `features.csv` / `features_factory.csv` — Внешние таблицы маршрутизации (LUT) для динамического маппинга визуальных стилей и параметров Z-Culling.

## 🏗 Ключевые архитектурные особенности

Успешный реверс-инжиниринг аппаратной стейт-машины платформы ATS3085S позволил реализовать в компиляторе следующие механизмы:

1. **C-Union Node Architecture**: Навигационные узлы (`Nav Node`) и узлы данных (`Data Node`) приведены к строгому унифицированному размеру в 28 байт. Согласно паттерну объединения (`union`) в языке C, последние 8 байт любого узла жестко зафиксированы под линки `v1` и `v2`. Это устранило проблему рассинхронизации аппаратного конвейера чтения.
2. **LOD Mode Switch**: Реализована поддержка динамического переключения режимов обработки пространственного индекса в заголовках `SQT\x01`. Для разреженных слоев или глубоких масштабов компилятор использует режим `Flat List (0x00)`, отбрасывая навигационные узлы ради экономии RAM. Для плотных данных применяется режим `Clustered (0x01)`.
3. **Hardware-Compensated Prefetch**: Формула расчета смещения относительного прыжка `v3_jump` скорректирована с учетом аппаратного упреждающего префетча процессора (`+8` байт), что обеспечивает корректное сквозное отсечение невидимых кластеров (Bounding Box Culling).
4. **Non-Zero Winding Rule**: Встроенный геометрический процессор строго следует правилу non-zero обхода контуров. Парсер компилятора принудительно нормализует полигоны: внешние границы ориентируются по часовой стрелке (`CW`), а внутренние островные пустоты (дырки) — строго против часовой стрелки (`CCW`).
5. **Memory Mapping Flags**: Системные флаги в глобальном 32-байтовом контейнере `YZL` приведены в соответствие с заводскими прошивками слоев (флаг `0x08` для магии и `0x02` для RAM-маппинга индексного файла).

## 🎨 Кастомизация стилей и LOD (features.csv)

Компилятор поддерживает динамический ремаппинг (переназначение) объектов OpenStreetMap в аппаратные стили часов через конфигурационный файл `features.csv`. Графический сопроцессор платформы ATS3085S не поддерживает передачу цвета в теле вектора, а использует жестко зашитую в ROM палитру (Look-Up Table), привязанную к системным ID объектов.

### Структура таблицы маршрутизации:
* `fclass`: Исходный класс объекта в OSM (например, `motorway`, `water`, `residential`).
* `Remap_Code`: Системный ID для прошивки часов. Изменяя этот код, вы меняете цвет объекта на экране (например, `5111` — толстая оранжевая линия, `5114` — желтая линия, `5124` — базовая серая линия, `8200` — синяя заливка воды).
* `Remap_LOD`: Порог аппаратного Z-Culling (в метрах). Определяет, при каком масштабе камеры объект появится на экране. Поддерживаемые уровни видимости: `1000` (LOD 2 - глобальный план), `500` (LOD 1 - средний план), `100`, `50`, `20` (LOD 0 - микро-геометрия).

**Пример кастомизации:** Чтобы сделать все второстепенные дороги серыми, найдите в CSV строку с классом `secondary` и измените значение `Remap_Code` на `5124`, а для скрытия их на общих планах установите `Remap_LOD` равным `100`.

> **Оригинальные заводские стили:** В репозитории присутствует файл `features_factory.csv`. Он содержит оригинальную, немодифицированную таблицу маршрутизации кодов. Если вам необходимо собрать карту с оригинальными (заводскими) стилями отрисовки, просто переименуйте этот файл в `features.csv` перед запуском компилятора.

Скрипты написаны на чистом Python 3 и используют исключительно стандартные библиотеки (`struct`, `json`, `os`, `hashlib`, `xml.etree.ElementTree`, `csv`). Внешние зависимости отсутствуют, что гарантирует стабильную кроссплатформенную компиляцию.
