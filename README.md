# DT G1 Map Tools (ATS3085S Platform)

Набор утилит на Python для реверс-инжиниринга, анализа и компиляции кастомных оффлайн-карт для смарт-часов **DT NO.1 G1** (и других устройств на базе аппаратной платформы **ATS3085S**).

Проект представляет собой полностью открытую реализацию компилятора и декомпилятора закрытого бинарного картографического формата. Инструментарий позволяет извлекать заводские карты в формат GeoJSON, а также собирать собственные карты из открытых источников (например, OpenStreetMap), которые аппаратно поддерживаются и рендерятся прошивкой часов.

## ⚠️ Дисклеймер
> Это неофициальный проект, созданный исключительно методом реверс-инжиниринга ("черного ящика" и побайтового анализа дампов памяти). Использование утилит и загрузка модифицированных файлов в часы осуществляется на ваш страх и риск.

## Состав инструментария

На данный момент кодовая база обеспечивает стопроцентную бинарную совместимость с аппаратным парсером часов и включает в себя:

* `dtg1_map_specification.md` — **Техническая спецификация формата.** Содержит полную структуру файлов `.mlp`, `.idx`, `.db`, спецификацию архитектуры C-Union, режимы переключения LOD и алгоритмы парсинга прошивки.
* `dtg1_map_compiler.py` — Компилятор карт версии. Автоматически парсит исходный XML-файл OpenStreetMap (`map.osm`), выполняет валидацию топологии полигонов, распределяет объекты по уровням детализации и генерирует готовые бинарные наборы (`.mlp`, `.idx`, `.db`) для слоев дорог, водоемов, землепользования и POI.
* `features.csv` / `features_factory.csv` — Внешние таблицы маршрутизации (LUT) для динамического маппинга визуальных стилей и параметров Z-Culling.

### Текущий статус реверс-инжиниринга (Roadmap)

- [x] Декодирование глобального заголовка YZL и расчет контрольных сумм MD5.
- [x] Реверс-инжиниринг структуры файлов геометрии (`.mlp`) — поддержка полилиний и сложных мультиполигонов (Winding Rules: Outer=CW, Inner=CCW).
- [x] Реверс-инжиниринг дерева пространственного индекса (`.idx`) — реализация State Machine (Flat List и Clustered Mode), аппаратный Z-Culling по масштабам (LOD 0, 1, 2).
- [x] Реверс-инжиниринг базы данных атрибутов (`.db`) — интеграция стандарта dBase III с поддержкой системных пустых записей (System Dummies).
- [x] Реверс-инжиниринг структуры точечных объектов инфраструктуры и интереса (`pois.idx/db`) — успешный разбор аппаратного маркера точечной топологии, инкапсуляции 32-битных координат в поля BBox узла данных и прямой (1-based) адресации dBase.

## Архитектура слоев карты

Скомпилированная карта состоит из набора слоев, каждый из которых включает триаду файлов (за исключением точечной геометрии):
* `*.mlp` — Файл сырой геометрии (массив координат вершин).
* `*.idx` — Пространственный индекс (SQT) для быстрого аппаратного отсечения невидимой геометрии (BBox Culling).
* `*.db` — База данных текстовых атрибутов (теги `name`).

**Поддерживаемые слои компилятора:**
1. `roads` (Линии) — дорожная сеть различных уровней.
2. `landuse` (Полигоны) — землепользование (парки, леса, жилая застройка).
3. `water` (Полигоны) — водоемы (используется системный ID рендеринга `8200` для заливки синим цветом).
4. `pois` (Точки) — объекты инфраструктуры (POI). *Примечание: слой имеет архитектурную аномалию, файл .mlp не используется, координаты хранятся непосредственно в графе индекса.*

## Требования к среде

* Python 3.8+
* Входные данные: файл `map.osm` (стандартный XML-экспорт OpenStreetMap).
* Конфигурация: файл `features.csv` (Look-Up Table стилей и маппинг кодов Geofabrik).

## Использование

1. Поместите исходный файл карты `map.osm` в корневую директорию компилятора.
2. Убедитесь, что конфигурационный файл `features.csv` содержит необходимые правила маппинга для целевой области.
3. Запустите скрипт сборки:
   ```bash
   python dtg1_map_compiler.py
   ```
4. Сгенерированные бинарные файлы (`.mlp`, `.idx`, `.db`) и загрузочный конфигуратор `map.name` будут сохранены в текущей директории и готовы к загрузке в файловую систему часов.


## Настройка стилей отображения и Z-Culling (features.csv)

Графический конвейер платформы ATS3085S не поддерживает передачу произвольных цветов (например, HEX или RGB) напрямую в файлах карт. Визуализация базируется на жестко зашитой в ROM таблице стилей (Look-Up Table / LUT). Цвет, толщина линии и заливка полигона определяются 32-битным системным идентификатором `code` (базирующимся на стандарте Geofabrik).
Управление аппаратным рендерингом и порогами видимости осуществляется через конфигурационный файл `features.csv`.

### Изменение стиля объекта (Remapping)

Для изменения внешнего вида картографического примитива применяется подмена его оригинального кода (перемаппинг) на этапе компиляции.
1. Откройте файл `features.csv` в табличном или текстовом редакторе.
2. Найдите целевой класс объекта в столбце `fclass` (например, `pedestrian` для пешеходной зоны).
3. Измените значение в столбце `Remap_Code` на идентификатор желаемого системного стиля.
   * *Пример:* Чтобы пешеходная улица отрисовывалась как широкая оранжевая автомагистраль, измените `Remap_Code` с `5124` на `5112` (код Motorway Link). Чтобы залить полигон синим цветом воды, используйте системный алиас `8200`.

### Управление дальностью прорисовки (Z-Culling)

Прошивка часов отсекает геометрию в зависимости от текущего масштаба GPS-камеры. Вы можете принудительно заставить объект рендериться на других масштабах.
* Столбец `Remap_LOD` в файле `features.csv` определяет порог видимости (Display Scale) в условных метрах.
* Распределение по бинарным секциям `.idx`:
  * `Remap_LOD >= 1000` — компилируется в секцию LOD 2 (всегда видны).
  * `Remap_LOD >= 500` — компилируется в секцию LOD 1 (средние масштабы).
  * `Remap_LOD < 500` — компилируется в базовую секцию LOD 0 (видны только вблизи).
* *Пример:* По умолчанию лесные массивы (`forest`) имеют `Remap_LOD = 500`. Чтобы лес был виден при максимальном отдалении камеры (глобальный вид), измените значение `Remap_LOD` на `1000`.

### Возврат к заводским настройкам (Factory Reset)

Оригинальная таблица стилей, построенная путем реверс-инжиниринга, сохранена в эталонном файле `features_factory.csv`.

Для отмены всех пользовательских модификаций цветов и уровней детализации:
1. Удалите текущий модифицированный рабочий файл `features.csv`.
2. Сделайте копию файла `features_factory.csv` и переименуйте ее в `features.csv`.
3. Запустите скрипт сборки `python dtg1_map_compiler.py` для перекомпиляции бинарных файлов `.mlp` и `.idx` с заводскими значениями `code`.
