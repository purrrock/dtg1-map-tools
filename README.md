# DT G1 Map Tools (C175C1 Platform)

Набор утилит на Python для реверс-инжиниринга, анализа и компиляции кастомных оффлайн-карт для смарт-часов **DT NO.1 G1** (и других устройств на базе аппаратной платформы **C175C1**).

Проект представляет собой полностью открытую реализацию компилятора и декомпилятора закрытого бинарного картографического формата. Инструментарий позволяет извлекать заводские карты в формат GeoJSON, а также собирать собственные карты из открытых источников (например, OpenStreetMap), которые аппаратно поддерживаются и рендерятся прошивкой часов .

## ⚠️ Дисклеймер
> Это неофициальный проект, созданный исключительно методом реверс-инжиниринга ("черного ящика" и побайтового анализа дампов памяти). Использование утилит и загрузка модифицированных файлов в часы осуществляется на ваш страх и риск.

## 🛠 Состав инструментария

Текущая кодовая база сфокусирована на обработке векторного слоя дорожной сети (`roads`).

* `dtg1_map_specification.md` — **Эталонная техническая спецификация формата.** Содержит полную структуру файлов `.mlp`, `.idx`, `.db`, адресацию памяти и алгоритмы парсинга прошивки.
* `dtg1_compiler.py` — Компилятор карт. Преобразует координаты линий в бинарный файл `.mlp` и генерирует промежуточные метаданные для сборки индекса. Создаёт пространственный индексс (`.idx`) и атрибутивную базу данных (`.db`). 
* `dtg1_idx_dumper.py` — Инструмент для низкоуровневого дебага. Дампит бинарное содержимое файлов `.idx` в читаемый CSV-формат с разметкой типов узлов.
* `dtg1_exporter.py` — Утилита обратного экспорта (Декомпилятор). Читает связку бинарных файлов часов (`.idx`, `.mlp`, `.db`) и конвертирует их в стандартный `GeoJSON` для просмотра в ГИС-редакторах.
* `dtg1_testmap_cli.py` — Утилита создания тестовой карты map.osm для отладки (для просмотра на часах различных типов линий).

## 🔬 Технические особенности (Открытия реверс-инжиниринга)

Долгое время создание кастомных карт приводило к зависанию (Soft Reset) потока рендеринга часов. В ходе глубокого анализа работы микропроцессора платформы C175C1 были выявлены две критические особенности аппаратного парсера, которые строго соблюдаются в данном компиляторе:

1. **Парадигма Плоского Списка (Flat List & State Machine):**
   Аппаратный рендерер часов **не поддерживает** иерархические деревья пространственных индексов (BVH, R-Tree). Индексный файл должен представлять собой строго одномерный массив (Flat List), считываемый конечным автоматом. Объекты группируются в кластеры максимум по 15 штук, разделяясь навигационными узлами (`Jump Pointers`) для отсечения невидимой геометрии (BBox Culling).

2. **Обход уязвимости `v2=0 Underflow`:**
   В заводской прошивке присутствует баг вычисления смещения адреса базы данных: `db_index = v2 - 1`. Если принудительно задать навигационному узлу (который не имеет собственных атрибутов) параметр `v2 = 0`, процессор обратится к памяти по индексу `-1`, что вызовет фатальный сбой. Наш компилятор реализует систему безопасного «наследования» параметров для обмана валидатора прошивки.

Подробное описание алгоритмов и побайтовых структур доступно в `dtg1_map_specification.md`.

## 🚀 Текущий статус и Roadmap

На данный момент проект успешно генерирует базовый уровень детализации (LOD 0) для слоя дорог. Карты стабильно отображаются на реальных устройствах.

**Планы на следующие релизы:**

- [ ] Интеграция парсера и компилятора для полигональных слоев: Землепользование (`landuse.idx/mlp/db`) и Водоемы (`water.idx/mlp/db`).
- [ ] Реверс-инжиниринг и внедрение слоя точечных объектов инфраструктуры (`pois.idx/db`).
- [ ] Создание единого CLI-интерфейса для сборки полного пакета карты в одну команду.

## 💻 Разработка и зависимости

Скрипты написаны на чистом Python 3 и используют стандартные библиотеки (структуры `struct`, `json`, `os`). Внешние зависимости сведены к минимуму для обеспечения максимальной портируемости.

```bash
# Пример использования дамп-утилиты
python dtg1_idx_dumper.py roads.idx

# Пример экспорта бинарников часов обратно в GeoJSON
python dtg1_exporter.py /path/to/map_folder
