Набор Python-утилит для реверс-инжиниринга, анализа и компиляции пользовательских офлайн-карт для смарт-часов DT NO.1 G1, VWAR, KKTICK и Amolde (а также других white-label устройств на базе аппаратной платформы Actions Semiconductor ATS3085S).
Инструментарий позволяет собирать собственные высокодетализированные карты из открытых источников (например, OpenStreetMap). Эти пользовательские карты аппаратно поддерживаются и идеально рендерятся встроенным графическим движком часов.

> **⚠️ Отказ от ответственности:** Это неофициальный проект, созданный исключительно путем реверс-инжиниринга (анализ "черного ящика" и побайтовый разбор дампов памяти). Использование данных утилит и прошивка модифицированных файлов в часы осуществляются на ваш собственный страх и риск.

## 🚀 Основные возможности компилятора

Компилятор был значительно модернизирован для обхода встроенных ограничений прошивки и оптимизации потребления ресурсов:
* **Поддержка огромных карт (Иерархические R-Деревья):** Генерирует истинные пространственные индексы по алгоритму STR (Sort-Tile-Recursive). Благодаря вложенным макро-узлам и расчету рекурсивных байтовых прыжков (`v3_jump`), аппаратный графический сопроцессор часов может отсекать целые области за одну инструкцию. Это обходит лимиты SRAM и обеспечивает плавный скроллинг на картах любого размера.
* **"Запекание" иконок POI (Points of Interest):** Обходит ограничение аппаратного графического конвейера (который нативно отбрасывает рендеринг POI) путем параметрического "запекания" точечных объектов в слой landuse. Генерирует низкополигональные геометрические примитивы (треугольники, квадраты, шестиугольники) с автоматической компенсацией искажения перспективы дисплея (Y-множитель = 1.5).
* **Программный куллинг (Early Exit парсинг):** Высокооптимизированный двухпроходной потоковый парсинг XML (`xml.etree.ElementTree.iterparse`). Немедленно отбрасывает отключенные узлы маршрутизации во время обхода дерева через 11-й столбец (`Enabled`) в конфигурации LUT.
* **Динамические аппаратные переопределения (Перехват тегов):** Переопределяет стандартные правила маршрутизации LUT "на лету" на основе многомерных OSM тегов.
    * *Анализ дорожного покрытия:* Динамически анализирует теги `surface` и `smoothness`. Автоматически понижает классы маршрутизации (например, primary roads) до грунтовых серых путей, если `smoothness=bad` или `surface=dirt`. Сохраняет оригинальные цвета LUT для неавтомобильной инфраструктуры (footways, cycleways) через внутреннюю маску исключений.
    * *Ограничения доступа:* Физические барьеры с ограниченным доступом (`access=private/no/permit`) перехватываются до вычисления LUT и принудительно преобразуются в розовые диагональные кресты.
* **Изоляция коллизий пространств имен:** Реестры черных списков (Blacklist) строго изолированы по слоям (`pois`, `roads`, `landuse`, `water`) для предотвращения конфликтов маршрутизации `fclass` между объектами разных категорий.
* **Интеграция GPX-треков:** Нативно компилирует пользовательские маршруты `.gpx` напрямую в аппаратный векторный граф.
* **Продвинутая маршрутизация по тегам ключ-значение:** Полностью парсит столбец `OSM_Tags` из `features.csv` для разрешения коллизий пространств имен. Объекты строго маршрутизируются с использованием точного поиска по хеш-таблице `key=value` (например, `shop=bicycle -> bicycle_shop`) перед применением эвристики fallback. Это гарантирует компиляцию всех сложных ГИС-классов без потери данных.

## 📂 Состав инструментария

Проект полностью перешел на **модульную архитектуру** для лучшей поддерживаемости и изолированной отладки. Кодовая база обеспечивает 100% бинарную совместимость с аппаратным парсером часов и включает:

* **`dtg1_map_compiler.py`** — Главный CLI-оркестратор. Координирует процесс сборки карты.
* **`dtg1_models.py`** — Структуры данных и системные константы (`MapFeature`, `HWConfig`).
* **`dtg1_osmparser.py`** — Логика парсинга карт и маршрутов (`OSMParser`, `GPXParser`).
* **`dtg1_geometry.py`** — Геометрические алгоритмы и "запекание" POI (`POIGeometryFactory`).
* **`dtg1_bin_writer.py`** — Низкоуровневая бинарная сериализация целевых файлов (`MapCompiler`).
* **`dtg1_lookup.py`** — Продвинутая конфигурация LUT и маршрутизация тегов (`LookupTables`).
* **`features.csv`** — Модифицируемая таблица маршрутизации стилей (LUT) с поддержкой программного куллинга (Blacklist).
* **`features_factory.csv`** — Оригинальный дамп заводской таблицы стилей.
* **`make_exe.cmd`** — Batch-скрипт для компиляции проекта в автономный `.exe` для Windows с помощью PyInstaller.
* **`dtg1_map_specification_ru.md`** — Техническая спецификация формата. Содержит побайтовую структуру файлов `.mlp`, `.idx` и `.db`.

## 📥 Загрузка и использование

Мы предоставляем готовые к использованию карты для популярных регионов, а также инструменты для сборки ваших собственных кастомных областей. Выберите вариант, который лучше всего соответствует вашим потребностям:

### Вариант A: Скачать предварительно скомпилированные карты (Самый простой)
Регулярно обновляемые, готовые к использованию пакеты карт для целых стран и регионов. Не требуется установка или компиляция.
1. Перейдите на страницу [**Latest Map Releases**](https://github.com/purrrock/dtg1-map-tools/releases/tag/latest-maps).
2. Скачайте архив `.zip` для нужного вам региона (например, `belarus_dtg1_map.zip`).
3. Распакуйте архив и скопируйте файлы (`roads.mlp`, `roads.idx`, `landuse.db`, `map.name`) напрямую во внутреннюю память часов через USB (обычно в папку `MAP/Map_Name`).

### Вариант B: Автономный компилятор (Только для Windows)
Идеально, если вы хотите скомпилировать кастомный Bounding Box или добавить личный маршрут GPX. Python не требуется.
1. [Скачайте последний релиз компилятора для Windows](https://github.com/purrrock/dtg1-map-tools/releases/latest).
2. Экспортируйте нужный участок карты из [OpenStreetMap](https://www.openstreetmap.org/export) как `map.osm`.
3. Поместите `dtg1_map_compiler.exe`, файл `features.csv` и ваши данные `map.osm` в одну папку.
4. Запустите исполняемый файл через командную строку (например, `dtg1_map_compiler.exe`).
5. Скопируйте выходные бинарные файлы на часы.

### Вариант C: Запуск из исходного кода (Для разработчиков и кроссплатформенный)
1. Убедитесь, что у вас установлен Python 3.10 или выше.
2. Клонируйте репозиторий и установите зависимости: `pip install -r requirements.txt`.
3. Поместите экспортированный файл `map.osm` в рабочую директорию рядом с компилятором.
4. Запустите скрипт: `python dtg1_map_compiler.py`.
5. Скопируйте сгенерированные файлы (`roads.mlp`, `roads.idx`, `landuse.db`, `map.name`) на часы через USB.

## ⚡ Предобработка больших карт (Настоятельно рекомендуется)

Если вы компилируете большие области, целые страны или сталкиваетесь с ошибками нехватки памяти (Out-Of-Memory) на вашем ПК во время компиляции, вам следует предварительно обработать исходный файл `.osm` с помощью утилиты `osm_optimizer.py`. Аппаратное обеспечение смарт-часов имеет ограничения. Рендеринг слишком длинных непрерывных линий (таких как главные магистрали) как единых объектов может привести к зависанию интерфейса часов или срабатыванию Soft Reset.

Оптимизатор решает эту проблему путем:
1.  **Аппаратно-безопасного чанкинга:** Безопасное разделение очень длинных линейных маршрутов на более мелкие сегменты (например, по 100 вершин на чанк) при сохранении математической топологии замкнутых полигонов (озера, леса) для предотвращения глитчей рендеринга.
2.  **Агрессивного удаления метаданных:** Удаление тяжелых метаданных OSM (метки времени, пользователи, наборы изменений) и отбрасывание глобально запрещенных тегов (например, `power`, `building`, `addr:*`) для значительного уменьшения размера промежуточного файла.

## ⚙️ Параметры интерфейса командной строки (CLI)

Компилятор реализует управление слоем объектов инфраструктуры (POI), вывод которого аппаратно подавляется графическим движком ATS3085S в текущих версиях прошивки.

Доступные флаги:
* `-h`, `--help` — Вывод справочной информации о доступных аргументах.
* `-p MODE`, `--poi-mode MODE` — Режим генерации базы данных объектов инфраструктуры (POI).
    * `none` — Полностью игнорировать POI при сборке. Защищает базу данных от раздувания.
    * `native` — Генерировать оригинальные бинарники `pois.idx` и `pois.db`. Полезно для тестирования реакции прошивки.
    * `landuse` (по умолчанию) — Интегрировать POI в слой landuse путем динамического "запекания" форм.

## 🎨 Кастомизация стилей и фильтрация объектов

Файл `features.csv` (Таблица поиска / Look-Up Table) является основным конфигурационным файлом компилятора. Он загружается динамически при каждом запуске.

### Структура таблицы LUT (11 столбцов)

Конфигурация состоит из 11 столбцов, разделенных точкой с запятой (`;`).
**Формат заголовка:**
```text
Code;fclass;Color;LOD;Layer;OSM_Tags;Description;Remap_Code;Remap_Color;Remap_LOD;Enabled;;Shape
```

**Параметры переназначения (алиасинга) имеют особое значение:**
* **Remap_Code:** Системный 32-битный ID, в который объект будет принудительно преобразован. 
    * *Пример:* Дороги с твердым покрытием маппятся в желтый цвет ID 5113.
* **Remap_LOD:** Аппаратная дистанция скрытия Z-Culling (в метрах), на которой объект появится на экране при масштабировании.

### Программный куллинг (Черный список)
Для защиты графического конвейера часов от переполнения ОЗУ и раздувания бинарного графа `.idx`, реализована система программного куллинга на этапе потокового парсинга. 11-й столбец конфигурации — `Enabled` — отвечает за фильтрацию.

* `1` (или `true`) — Объект загружается в компилятор и участвует в генерации карты.
* `0` (или `false`) — Приглушенный класс. Отбрасывается аппаратно. Алгоритм использует прерывание парсинга Early Exit: при встрече тега со значением `Enabled=0`, парсер немедленно отбрасывает XML-узел до вычисления Bounding Box. Это экономит процессорное время и предотвращает замену исключенных объектов стилями по умолчанию (серыми или зелеными).

### Сброс к заводским настройкам
Оригинальная таблица стилей, полученная путем реверс-инжиниринга, сохранена в эталонном файле `features_factory.csv`. Чтобы отменить все пользовательские изменения цветов, черных списков и уровней детализации:
1.  Удалите текущий измененный рабочий файл `features.csv`.
2.  Сделайте копию файла `features_factory.csv` и переименуйте ее в `features.csv`.
3.  Запустите скрипт сборки, чтобы перекомпилировать бинарники с заводскими значениями параметров.

## 🗺️ Инъекция пользовательских маршрутов (GPX)

Компилятор поддерживает прямую инъекцию навигационных треков поверх базовой карты.

1.  Поместите файлы ваших маршрутов (`*.gpx`) в директорию `routes/`.
2.  Запустите сборку. Скрипт автоматически найдет трек и извлечет его имя. Извлеченная строка компилируется в атрибутивную базу данных `roads.db`, гарантируя, что трек сохранит свое оригинальное имя на часах.
3.  Инжектированный GPX-трек преобразуется в объект со специфическим типом `5111` (Motorway). Этот код аппаратно зарезервирован в прошивке часов для рендеринга жирной, контрастной оранжевой линии. Чтобы запланированный маршрут не сливался с реальными автомагистралями, все объекты motorway из исходного OSM-файла принудительно понижаются в масштабе до желтого типа `5112` (Trunk) путем подмены кода в `features.csv`.

*Примечание: Чтобы отключить инъекцию и собрать чистую карту, просто удалите файлы GPX перед запуском.*

## 🔬 Инструменты реверс-инжиниринга (`/tools`)

В репозиторий включены внутренние скрипты, использовавшиеся в процессе реверс-инжиниринга графического конвейера ATS3085S:
* `dtg1_idx_dumper.py` — Декомпилятор, извлекающий пространственные индексы `.idx` в читаемые CSV-форматы для бинарного анализа.
* `roads_fuzzer.py` — Генерирует координатную сетку геометрических примитивов для тестирования аппаратного рендеринга Z-Index и структурных лимитов C-Union.
