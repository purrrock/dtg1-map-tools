# Кастомные офлайн-карты для DT NO.1 G1 / VWAR / KKTICK / Amolde HD300 Pro (Аппаратная платформа ATS3085S, ОС Zephyr RTOS)

Набор Python-утилит для реверс-инжиниринга, анализа и компиляции пользовательских офлайн-карт для смарт-часов **DT NO.1 G1**, **VWAR**, **KKTICK** и **Amolde** (а также других white-label устройств на базе аппаратной платформы **Actions Semiconductor ATS3085S**).

Если вы ищете способ **установить свои карты на смарт-часы** или нуждаетесь в более детализированных **офлайн-картах для DT NO.1 G1** для синхронизации через приложение **WearPro**, данный проект предоставляет полноценное open-source решение. 

Инструментарий позволяет собирать собственные высокодетализированные карты из открытых источников (например, OpenStreetMap). Эти пользовательские карты аппаратно поддерживаются и идеально рендерятся встроенным графическим движком часов.

> **⚠️ Отказ от ответственности** > Это неофициальный проект, созданный исключительно путем реверс-инжиниринга (анализ "черного ящика" и побайтовый разбор дампов памяти). Использование данных утилит и прошивка модифицированных файлов в часы осуществляются на ваш собственный страх и риск.

## 🚀 Основные возможности компилятора

Компилятор был значительно модернизирован для обхода встроенных ограничений прошивки и оптимизации потребления ресурсов:

* **"Запекание" иконок POI (Points of Interest):** Обходит ограничение аппаратного графического конвейера (который нативно отбрасывает рендеринг POI) путем  "запекания" точечных объектов в слой `landuse`. Генерирует низкополигональные геометрические примитивы (треугольники, квадраты, шестиугольники...) с автоматической компенсацией искажения перспективы дисплея (Y-множитель = 1.5).
* **Программный куллинг (Early Exit парсинг):** Высокооптимизированный двухпроходной потоковый парсинг XML (`xml.etree.ElementTree.iterparse`). Немедленно отбрасывает отключенные узлы маршрутизации во время обхода дерева на основе 11-го столбца (`Enabled`) в конфигурации LUT.
* **Динамические аппаратные переопределения:** Переопределяет стандартные правила таблицы маршрутизации для специфических сущностей. Например, физические барьеры с ограниченным доступом (`access=private/no/permit`) автоматически перехватываются до вычисления LUT и принудительно преобразуются в розовые диагональные кресты (Аппаратный код: `7209`).
* **Изоляция коллизий пространств имен:** Реестры черных списков (Blacklist) строго изолированы по слоям (`pois`, `roads`, `landuse`, `water`) для предотвращения конфликтов маршрутизации `fclass` между объектами разных категорий.
* **Интеграция GPX-треков:** Нативно компилирует пользовательские маршруты `.gpx` напрямую в аппаратный векторный граф.
* **Продвинутая маршрутизация по тегам ключ-значение:** Полностью парсит столбец `OSM_Tags` из `features.csv` для разрешения коллизий пространств имен. Объекты строго маршрутизируются с использованием точного поиска по хеш-таблице `key=value` (например, `shop=bicycle` -> `bicycle_shop`) перед применением эвристики fallback. Это гарантирует компиляцию всех сложных ГИС-классов без потери данных.

## Состав инструментария

В настоящее время кодовая база обеспечивает 100% бинарную совместимость с аппаратным парсером часов и включает:

* `dtg1_map_specification.md` — **Техническая спецификация формата.** Примечание: полная документация по бинарной структуре вынесена в этот отдельный файл. Он содержит побайтовую структуру файлов `.mlp`, `.idx` и `.db`, спецификацию архитектуры C-Union, режимы переключения LOD и алгоритмы парсинга.
* `dtg1_map_compiler.py` — Компилятор векторных карт. Автоматически парсит исходный XML-файл OpenStreetMap (`map.osm`), выполняет валидацию топологии, распределяет объекты по уровням детализации, применяет алиасинг стилей и генерирует готовые к использованию пакеты файлов.
* `features.csv` — Модифицируемая таблица маршрутизации стилей (LUT) с поддержкой программного куллинга (Blacklist).
* `features_factory.csv` — Оригинальный дамп заводской таблицы стилей (для резервного копирования и сброса к заводским параметрам отображения).

## Установка и быстрый старт

1. Убедитесь, что у вас установлен Python 3.8 или выше. Дополнительные сторонние зависимости не требуются (проект использует исключительно встроенные модули: `os`, `struct`, `xml.etree`, `csv`, `math`, `argparse`).
2. Экспортируйте нужный участок карты из [OpenStreetMap](https://www.openstreetmap.org/export) в формате XML.
3. Переименуйте скачанный файл в `map.osm` и поместите его в директорию компилятора.
4. Минимально необходимые файлы для сборки: `dtg1_map_compiler.py` и `features.csv`.
5. Запустите скрипт компиляции. Скомпилированные файлы (`roads.mlp`, `roads.idx`, `landuse.db`, `map.name` и т.д.) появятся в текущей директории.
6. Скопируйте сгенерированные файлы во внутреннюю память часов (обычно в папку `MAP/Map_Name` через USB-подключение).

## Параметры интерфейса командной строки (CLI)

Компилятор реализует управление слоем объектов инфраструктуры (POI), вывод которого аппаратно подавляется графическим движком ATS3085S в текущих версиях прошивки.

**Синтаксис запуска:**
~~~bash
python dtg1_map_compiler.py [аргументы]
~~~

**Доступные флаги:**
* `-h`, `--help` — Вывод справочной информации о доступных аргументах.
* `-p MODE`, `--poi-mode MODE` — Режим генерации базы данных объектов инфраструктуры (POI).
    * `none` *(по умолчанию)* — Полностью игнорировать POI при сборке. Защищает базу данных от раздувания.
    * `native` — Генерировать оригинальные бинарники `pois.idx` и `pois.db`. Полезно для тестирования реакции прошивки.
    * `landuse` — Интегрировать POI в слой landuse.

## Кастомизация стилей и фильтрация объектов

Файл `features.csv` (Таблица поиска / Look-Up Table) является основным конфигурационным файлом компилятора. Он загружается динамически при каждом запуске.

### Структура таблицы LUT (11 столбцов)

Конфигурация состоит из 11 столбцов, разделенных точкой с запятой (`;`).
**Формат заголовка:**
~~~text
Code;fclass;Color;LOD;Layer;OSM_Tags;Description;Remap_Code;Remap_Color;Remap_LOD;Enabled;;Shape
~~~

**Параметры переназначения (алиасинга) имеют особое значение:**
* **Remap_Code:** Системный 32-битный ID, в который объект будет принудительно преобразован. 
    * *Пример:* Дороги с твердым покрытием маппятся в желтый цвет ID 5113.
* **Remap_LOD:** Аппаратная дистанция скрытия Z-Culling (в метрах), на которой объект появится на экране при масштабировании.

### Программный куллинг (Черный список)

Для защиты графического конвейера часов от переполнения ОЗУ и раздувания бинарного графа `.idx`, реализована система программного куллинга на этапе потокового парсинга. За фильтрацию отвечает 11-й столбец конфигурации — **`Enabled`**.

* **`1` (или `true`)** — Объект загружается в компилятор и участвует в генерации карты.
* **`0` (или `false`)** — Приглушенный класс. Отбрасывается аппаратно. 

Алгоритм использует прерывание парсинга Early Exit: при встрече тега со значением `Enabled=0`, `OSMParser` немедленно отбрасывает XML-узел до вычисления Bounding Box (ограничивающего прямоугольника). Это экономит процессорное время и предотвращает замену исключенных объектов стилями по умолчанию (серыми или зелеными).

## Инъекция пользовательских маршрутов (GPX)

Компилятор поддерживает прямую инъекцию навигационных треков поверх базовой карты.
    
1. Поместите файл вашего маршрута с именем `route.gpx` в корневую директорию проекта.
2. Запустите сборку. Скрипт автоматически найдет трек и извлечет его имя из тега `<name>`. Извлеченная строка компилируется в атрибутивную базу данных `roads.db`, гарантируя, что трек сохранит свое оригинальное имя на часах.
3. Инжектированный GPX-трек преобразуется в объект со специфическим типом `5111` (Motorway). Этот код аппаратно зарезервирован в прошивке часов для рендеринга жирной, контрастной оранжевой линии. Чтобы запланированный маршрут не сливался с реальными автомагистралями, все объекты `motorway` из исходного OSM-файла принудительно понижаются в масштабе до желтого типа `5112` (Trunk) путем подмены кода в `features.csv`.

> **Примечание:** Чтобы отключить инъекцию и собрать чистую карту, просто удалите или переименуйте файл `route.gpx` в корневой директории компилятора перед запуском.

## Сброс к заводским настройкам

Оригинальная таблица стилей, полученная путем реверс-инжиниринга, сохранена в эталонном файле `features_factory.csv`.

Чтобы отменить все пользовательские изменения цветов, черных списков и уровней детализации:
1. Удалите текущий измененный рабочий файл `features.csv`.
2. Сделайте копию файла `features_factory.csv` и переименуйте ее в `features.csv`.
3. Запустите скрипт сборки `python dtg1_map_compiler.py`, чтобы перекомпилировать бинарники `.mlp` и `.idx` с заводскими значениями параметров.

## 🛠 Инструменты реверс-инжиниринга (/tools)
В репозиторий включены внутренние скрипты, использовавшиеся в процессе реверс-инжиниринга графического конвейера ATS3085S:

* `dtg1_idx_dumper.py` — Декомпилятор, извлекающий пространственные индексы `.idx` в читаемые CSV-форматы для бинарного анализа.
* `roads_fuzzer.py` — Генерирует координатную сетку геометрических примитивов для тестирования аппаратного рендеринга Z-Index и структурных лимитов C-Union.
* И другие инструменты.
