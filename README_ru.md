# DT G1 Map Tools (ATS3085S Platform)

Набор утилит на Python для реверс-инжиниринга, анализа и компиляции кастомных оффлайн-карт для смарт-часов **DT NO.1 G1** (и других устройств на базе аппаратной платформы **ATS3085S**).

Проект представляет собой полностью открытую реализацию компилятора и декомпилятора закрытого бинарного картографического формата. Инструментарий позволяет извлекать заводские карты в формат GeoJSON, а также собирать собственные карты из открытых источников (например, OpenStreetMap), которые аппаратно поддерживаются и рендерятся прошивкой часов.

> **⚠️ Дисклеймер** > Это неофициальный проект, созданный исключительно методом реверс-инжиниринга ("черного ящика" и побайтового анализа дампов карт). Использование утилит и загрузка модифицированных файлов в часы осуществляется на ваш страх и риск.

## Состав инструментария

На данный момент кодовая база обеспечивает стопроцентную бинарную совместимость с аппаратным парсером часов и включает в себя:

* `dtg1_map_specification.md` — **Техническая спецификация формата.** Внимание: полная документация по структуре бинарников вынесена в этот отдельный файл. Он содержит побайтовую структуру файлов `.mlp`, `.idx`, `.db`, спецификацию архитектуры C-Union, режимы переключения LOD и алгоритмы парсинга графического движка прошивки.
* `dtg1_map_compiler.py` — Компилятор векторных карт. Автоматически парсит исходный XML-файл OpenStreetMap (`map.osm`), выполняет валидацию топологии, распределяет объекты по уровням детализации, применяет алиасинг стилей и генерирует готовые пакеты файлов.
* `features.csv` — Модифицируемая таблица маршрутизации стилей (LUT) с поддержкой программного отсечения (Blacklist).
* `features_factory.csv` — Оригинальный дамп заводской таблицы стилей (для бэкапа и сброса к заводским параметрам отображения).

## Установка и быстрый старт

1.  Убедитесь, что у вас установлен Python 3.8 или выше. Дополнительные сторонние зависимости не требуются (проект использует исключительно встроенные модули: `os`, `struct`, `xml.etree`, `csv`, `math`, `argparse`).
2.  Экспортируйте нужный участок карты с [OpenStreetMap](https://www.openstreetmap.org/export) в формате XML.
3.  Переименуйте скачанный файл в `map.osm` и поместите в папку с компилятором.
4.  Минимально необходимые для сборки файлы: `dtg1_map_compiler.py` и `features.csv`.
5.  Запустите скрипт компиляции. Скомпилированные файлы (`roads.mlp`, `roads.idx`, `landuse.db`, `map.name` и др.) появятся в текущей директории.
6.  Скопируйте сгенерированные файлы во внутреннюю память часов (обычно в папку `MAP/Имя_карты` через USB-подключение).

## Параметры командной строки (CLI)

Компилятор поддерживает управление пайплайном сборки через встроенный модуль `argparse`. На данный момент реализовано управление слоем точечных объектов (POI), вывод которого аппаратно подавляется графическим движком ATS3085S в текущих версиях прошивок.

**Синтаксис запуска:**
```bash
python dtg1_map_compiler.py [аргументы]
```

**Доступные ключи:**
* `-h`, `--help` — Вывод справочной информации по доступным аргументам.
* `-p MODE`, `--poi-mode MODE` — Режим генерации базы точечных объектов (POI).
    * `none` *(по умолчанию)* — Полностью игнорировать POI при сборке. Защищает базу данных от раздувания.
    * `native` — Сгенерировать оригинальные бинарники `pois.idx` и `pois.db`. Полезно для тестирования реакции прошивки.
    * `landuse` — Интеграция POI в слой землепользования.

## Кастомизация стилей и Фильтрация объектов

Файл `features.csv` (Look-Up Table) является главным конфигурационным файлом компилятора. Он загружается динамически при каждом запуске.

### Структура таблицы LUT (11 столбцов)

Конфигурация состоит из 11 столбцов, разделяемых точкой с запятой (`;`).
**Формат заголовка:**
```text
Code;fclass;Color;LOD;Layer;OSM_Tags;Description;Remap_Code;Remap_Color;Remap_LOD;Enabled
```

**Особое значение имеют параметры ремаппинга (алиасинга):**
* **Remap_Code:** Системный 32-битный ID, в который будет принудительно сконвертирован объект. 
    * *Пример :* Дороги с твердым покрытием маппятся в желтый цвет ID 5113.
* **Remap_LOD:** Дистанция аппаратного скрытия Z-Culling (в метрах), на которой объект появится на экране при масштабировании.

### Программное отсечение (Software Culling / Blacklist)

Для защиты графического конвейера часов от переполнения оперативной памяти и раздувания бинарных графов `.idx` реализована система программного отсечения на этапе потокового парсинга. За фильтрацию отвечает 11-й столбец конфигурации — **`Enabled`**.

* **`1` (или `true`)** — Объект загружается в компилятор и участвует в формировании карт.
* **`0` (или `false`)** — Заглушенный класс. Аппаратно отсекается. 

Алгоритм использует прерывание парсинга (Early Exit): при встрече тега со значением `Enabled=0` парсер `OSMParser` немедленно отбрасывает XML-узел до вычисления Bounding Box. Это экономит процессорное время и предотвращает подмену исключенных объектов дефолтными серыми или зелеными стилями.

## Инъекция пользовательских маршрутов (GPX)

Компилятор поддерживает прямое внедрение навигационных треков поверх базовой карты.
    
1.  Поместите ваш файл маршрута с именем `route.gpx` в корневую директорию проекта.
2.  Запустите сборку. Скрипт автоматически найдет трек и извлечет его название из тега `<name>`. Извлеченная строка компилируется в атрибутивную базу данных `roads.db`, благодаря чему трек сохраняет на часах свое оригинальное имя.
3.  Внедренный GPX-трек преобразуется в объект со специфическим типом `5111` (Motorway). Данный код аппаратно зарезервирован в прошивке часов под отрисовку жирной, контрастной оранжевой линией. Чтобы плановый маршрут не сливался с реальными автомагистралями, все объекты `motorway` из исходного OSM-файла принудительно даунскейлятся до желтого типа `5112` (Trunk) через подмену кодов в `features.csv`.

> **Примечание:** Для отключения инъекции и сборки чистой карты достаточно удалить или переименовать файл `route.gpx` в корневом каталоге компилятора перед запуском.

## Возврат к заводским настройкам (Factory Reset)

Оригинальная таблица стилей, построенная путем реверс-инжиниринга, сохранена в эталонном файле `features_factory.csv`.

Для отмены всех пользовательских модификаций цветов, блэклистов и уровней детализации:
1.  Удалите текущий модифицированный рабочий файл `features.csv`.
2.  Сделайте копию файла `features_factory.csv` и переименуйте ее в `features.csv`.
3.  Запустите скрипт сборки `python dtg1_map_compiler.py` для перекомпиляции бинарных файлов `.mlp` и `.idx` с заводскими значениями параметров.

dtg1_idx_dumper.py — Декомпилятор, выгружающий пространственные индексы .idx в читаемый CSV-формат для побайтового анализа.
roads_fuzzer.py — Генератор координатной сетки геометрических примитивов для тестирования аппаратного Z-Index рендеринга и лимитов структур C-Union.
И прочие инструменты.
